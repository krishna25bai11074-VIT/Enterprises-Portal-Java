# Project Report — Swades Enterprises Portal

## 1. Problem Statement

Small and medium retail enterprises struggle with manual GST calculations,
inconsistent invoice formatting, and tedious customer reward processes.
Manual tax calculations are error-prone, leading to incorrect billing and
poor customer experience.

This project attempts to solve a simple but meaningful question —
**"Can we build a unified, terminal-based Java portal to automate GST analytics,
invoice generation, and customer record management efficiently?"**

---

## 2. Why This Problem Matters

- India has millions of small and medium enterprises (MSMEs) processing GST daily
- Manual tax percentage calculations and invoice drafting lead to costly billing errors
- Small shop owners need a lightweight, zero-dependency tool without complex database setups
- Interactive CLI dashboards enable fast point-of-sale interaction for store managers

---

## 3. Dataset

- **Source:** In-memory data store initialized via `Data.java`
- **Records:** Initial dataset of customer purchases (Krishna, Aashutosh, Ravi, Bhavya, Ishant)
- **Features collected:** Customer Name, Product Name, Sale Price (₹), GST Percentage (%), GST Rate (₹)
- **Data Management:** Dynamic append functionality for adding new sales transactions during runtime

No external database installation was needed — data structures are managed in-memory via Java Collections.

---

## 4. Approach

### Step 1 — Data Architecture (`Data.java`)
Defined a static `Record` model class and initialized an in-memory `Info` collection storing transaction details with strongly typed fields.

### Step 2 — Analytics & Statistical Operations (`Main.java`)
- Implemented mathematical and statistical helper routines (`getMax`, `getMin`, `getMean`, `getSum`, `getMode`)
- Derived metrics for Sale Prices, GST Percentages, and GST Rates

### Step 3 — Invoice Generator Module
- Prompt-driven data collection for Enterprise name, address, shipping details, and product info
- Custom ASCII text box renderer (`padCenter`, `padLeft`) to print formatted invoices directly in console

### Step 4 — Customer Reward & Interactive Dashboard
- Implemented random customer winner selection (`java.util.Random`) for anniversary specials
- Built a loop-driven interactive CLI dashboard using `java.util.Scanner`

---

## 5. Key Decisions Made

**Why port from Python to Java?**
Java provides strong static typing, cross-platform portability via the Java Virtual Machine (JVM), and superior runtime stability for business enterprise applications.

**Why use Scanner and custom statistical routines?**
Avoids external library dependencies, keeping the application lightweight, standalone, and instant to compile and execute on any system with Java installed.

**Why format numbers dynamically (`formatNum`)?**
Ensures whole amounts display cleanly without trailing decimal zeros (e.g. `180000` instead of `180000.0`), matching professional receipt standards.

## 6. Results

- All 5 dashboard options execute seamlessly in the terminal
- Statistical calculations (highest, lowest, average, total, most frequent) perform instantly on transaction datasets
- Invoices render with clean, aligned borders and itemized GST breakdowns
- New sales records persist in-memory across dashboard operations within the session

## 7. Challenges Faced

**Challenge 1 — Type Conversion & Input Buffering**
Mixing integer/double inputs with line strings in Java `Scanner` can lead to skipped line inputs. Fixed by reading lines with `scanner.nextLine()` and parsing integers/doubles explicitly.

**Challenge 2 — Mode Calculation for Datasets**
Java standard library does not have a built-in `statistics.mode()` like Python. Implemented custom `getMode()` using `HashMap` frequency tracking.

**Challenge 3 — Text Formatting & Alignment in Console**
Dynamic product titles and rates broke ASCII box borders. Solved by writing `padCenter` and `padLeft` padding utility functions.

**Challenge 4 — Handling Case-Insensitive User Loop Inputs**
User inputs like 'y' or 'Y' needed graceful handling without throwing errors. Implemented robust string parsing and exception fallback logic.
